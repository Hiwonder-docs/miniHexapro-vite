4.1 WonderLLM Module Introduction ​

WonderLLM is an AI module equipped with an ESP32-P4 high-performance chip and an ESP32-C5 dual-band Wi-Fi 6 chip. It integrates a 2MP HD camera, microphones, an HD display screen, a speaker, and a CI1302 audio chip, deeply fusing text, voice, and visual modalities.

The module features straightforward operation and is designed to pair with robots as an intelligent processing hub. It interprets complex instructions and empowers robots with perception, reasoning, and execution capabilities for natural human-robot interaction.

4.1.1 Working Principle ​

  1. The module uses voice commands for activation. State the wake word to activate WonderLLM before starting human-robot interaction. The default system language is English, and the default English wake word is Hello Hiwonder.

  2. Once the module recognizes the wake word, the buzzer emits a single beep, indicating readiness for interaction. The module supports communication in both English and Chinese, automatically detecting and switching to the spoken language. If no voice input is detected within 1 minute, the module enters sleep mode. Reactivate the module using the wake word for subsequent use.

  3. The wake word can be modified, and custom entries can be defined. Refer to 4.9 Wake Word Modification for detailed configuration steps.

  4. To flash English firmware, refer to 4.10 Firmware Flashing for firmware flashing procedures.

4.1.2 Precautions ​

  1. Power the module strictly with a 5 V power supply, as incorrect voltage can damage internal circuits.

  2. Operate the module in a quiet environment, as noisy conditions degrade speech recognition performance.

  3. Speak clearly at a moderate pace when delivering voice commands. Maintain a distance of within 5 m from the module for optimal reception.

4.1.4 Powering On the Device ​

NOTE

The WonderLLM AI module provides both Chinese and English factory firmware. If the factory firmware language does not match project requirements upon powering on, refer to 4.9.2 CI1302 Firmware Flashing and 4.10 Firmware Flashing to flash the corresponding firmware versions.

  1. The module supports three power supply inputs: the upper Type-C port, the lower Type-C port, and the 4-pin I2C communication interface. Connect an external power supply to any of these interfaces to power on the module automatically.
  1. Upon powering on for the first time, the screen displays the Wi-Fi hotspot name and the browser network configuration URL, accompanied by a voice prompt. Complete network configuration by following the steps in 4.2 Network Connection and Configuration.
  1. After network configuration, bind the module to the cloud platform agent. The screen displays the Device ID and the platform binding URL, accompanied by a voice broadcast of the binding verification code. Complete device binding according to 4.2 Network Connection and Configuration, where XXXXXX below the binding URL represents the Device ID.
  1. If the device has already been bound, a white rotating circle appears on the screen upon powering on, indicating that the module is connecting to the network using stored Wi-Fi credentials. If the network connection fails, the screen displays the device hotspot name and access URL accompanied by a voice prompt. Configure accessible Wi-Fi credentials again according to 4.2 Network Connection and Configuration.
  1. If the device is bound and the configured Wi-Fi is accessible, the white circular progress bar finishes loading and the screen switches to the expression interface, confirming network connection. The module is now ready for voice activation and interactive tasks.

4.2 Network Connection and Configuration ​

4.2.1 Module Network Connection ​

  • Operational Steps
  1. The module attempts to connect to the network automatically upon power-up. The module enters network configuration mode under three conditions: ① during initial use or after firmware reflashing when no Wi-Fi credentials exist in memory, ② when no available hotspot matches stored Wi-Fi credentials, or ③ through manual trigger by long-pressing button B on the right.
  1. The screen displays the device hotspot name and the access URL accompanied by a voice prompt. The module launches an onboard Wi-Fi hotspot for configuration. Hotspot names vary across devices in the format Robot-xxxx. This guide uses hotspot Robot-B7B9 as an example.
  1. Search for the corresponding hotspot on a PC or smartphone and connect to it without a password.
  1. Open a web browser and navigate to http://192.168.4.1, or click Network Configuration to open the configuration interface directly.
  1. Click the language button to toggle the display language.
  1. Enter the target Wi-Fi SSID in field ① and enter the corresponding password in field ②. Click Connect in field ③. The module will search for the specified network and establish a connection.

NOTE

  • Do not enter credentials for undetected Wi-Fi networks, networks with weak signals, or networks without internet access.

  • If credentials for other hotspots are already stored in the module, new network credentials will coexist with them. On the next startup, the module attempts connection sequentially based on the saved order.

  1. The interface displays detected available Wi-Fi networks. Clicking a listed SSID automatically populates field ①, simplifying input.
  1. If an error prompt appears as shown below, the hotspot cannot be located or the password is incorrect. Re-enter the credentials.
  1. The following prompt confirms successful connection. The module reboots automatically and connects to the target network. Initial setup is complete, and subsequent course features can now be accessed.

NOTE

If the screen displays an error stating that checking for new versions failed and will retry in xx seconds after network configuration, the connected hotspot may lack internet access or experience unstable connectivity. Switch to another network.

  • Manually Entering Network Configuration Mode

  1. The WonderLLM AI module supports manual entry into network configuration mode, allowing flexible connection to alternative networks.

  2. After powering on the module, press and hold the right button to send a restart command. The screen turns off upon receiving the command. Continue holding the button. As the module restarts and begins connecting to the network, a white circular progress bar appears on the screen. The module detects the sustained button press, bypasses automatic connection, and enters network configuration mode directly. Release the button once the configuration interface appears.

  3. Existing Wi-Fi configurations remain saved upon entering network configuration mode. Proceed to configure new network settings on the web page, or press the right button briefly to exit network configuration mode.

  4. Upon exiting network configuration mode, the module resumes connection attempts using saved network profiles. If no stored network is accessible, the module returns to network configuration mode automatically.

  • Managing Saved Connection Configurations (Optional)
  1. While in network configuration mode, connect to the module hotspot and open the configuration page to view all saved Wi-Fi connection profiles, as shown below:
  1. Click beside any saved Wi-Fi profile to delete it, or click to raise its connection priority, where priority decreases from top to bottom.

4.2.3 Device Unbinding ​

  1. When following the binding workflow in 4.2.2 Device Binding, if the module interface displays the device ID and binding website, and it is bound to the XiaoZhi AI platform according to the subsequent steps, the current user will be considered the first user of this module. For after-sales service, return, or transfer of the first user's identity, follow the First User Unbinding steps outlined below.
  1. If the binding prompt does not appear, the module has already been bound to an existing account as a secondary device. The module remains functional, but agent configuration cannot be modified. Follow the Third-Party User Unbinding procedure to release the module from the prior account, and then complete 4.2.2 Device Binding to register as the primary owner.
  • First User Unbinding
  1. Open a browser and visit https://xiaozhi.me/, or click XiaoZhi AI Chatbot for direct access.
  1. Click Console to access the XiaoZhi AI agent management platform.
  1. Select the corresponding device and click Management Devices.
  1. Click the X button, then click Certainty to unbind the device.
  • Third-Party User Unbinding

  1. Unbinding an account without administrative access requires submitting the MAC address and Device ID to XiaoZhi AI official technical support. Obtain these details using the procedure below.

  2. Open the serial port debugging tool located at 2. Software Tools & Programs/6. Serial Port Debugging Tool. Connect the USB cable between the computer and the lower Type-C port on the module, then select the corresponding COM port to open the connection. The module outputs log data through this serial interface. Locate the Wifi Mode entry in the serial log and copy the current MAC address listed under the sta field for subsequent use.

NOTE

If the target log entry does not appear after 1 minute of monitoring serial output, the log line may have been transmitted before the serial port debugging tool connected. Keep the serial tool active, disconnect and reconnect the USB cable to power-cycle the module, and observe the retransmitted startup logs.

  1. Connect the module to the network. Enter the chat interface by stating the wake word or pressing the right button briefly. Once the module activates, retrieve the Device ID by speaking to the model using the following prompt: "Please tell me your device ID."

  2. Compile this information and send an email to XiaoZhi AI technical support at xiaozhi.ai@tenclass.com. Format the email subject according to the template: "Unbind the device, device ID [Input device ID here], MAC address [Input MAC address here]". The email body is optional.

  1. Technical support will reset the device binding status after reviewing the request and will confirm completion via email. Once confirmed, bind the module to a personal account.
  • Voice Command Unbinding

State the voice command "Confirm device deletion" to unbind the device directly.

4.3 Volume Control ​

NOTE

Before proceeding with this section, ensure the module is powered on and Wi-Fi and agent configurations are completed according to 4.1 WonderLLM Module Introduction and 4.2 Network Connection and Configuration.

This section introduces manual and voice-controlled volume adjustment for the WonderLLM AI module to optimize interaction.

4.3.1 Adjusting Volume via Touchscreen ​

  1. Once the module connects to an external Wi-Fi network, adjust the speaker volume via the touchscreen in either of two interfaces: the expression interface or the chat interface.

NOTE

The expression interface is the default display after network connection. The chat interface is accessed by stating the wake word or pressing the right button, as detailed in 4.4 Chat Mode.

  1. To adjust the volume, swipe vertically on the screen in either interface. Swiping upward increases the volume, while swiping downward decreases the volume. The adjustment step depends on the swipe distance, and multiple swipes can be performed consecutively.

NOTE

Volume adjustments made while WonderLLM is speaking take effect during the subsequent speech cycle.

  1. Swiping the screen displays real-time volume levels at the top of the display. The example below illustrates increasing the volume by swiping upward in the expression interface:

4.3.2 Adjusting Volume via Voice Commands (Optional) ​

  1. Speaker volume can also be regulated using spoken voice commands during interaction with the WonderLLM AI module.

  2. Say the wake word or press the right button briefly to enter the chat interface. Once activated, issue commands using sample phrases such as: "Set volume to xx", where valid values range from 0 to 100 as integers or percentages, or "Increase volume" for relative adjustment.

NOTE

  • Volume adjustments made while WonderLLM is speaking take effect during the subsequent speech cycle.

  • Commands do not require exact phrasing as long as the semantic meaning is preserved.

  1. Upon speech recognition, the chat box indicates the invoked volume control function, which requires no manual intervention, followed by the response message and voice broadcast. Responses are generated dynamically while maintaining appropriate context.

4.4 Chat Mode ​

NOTE

Before proceeding with this section, ensure the module is powered on and Wi-Fi and agent configurations are completed according to 4.1 WonderLLM Module Introduction and 4.2 Network Connection and Configuration.

4.4.1 Mode Overview ​

  1. This section introduces Chat Mode, where the module listens to spoken input, interprets semantic intent, and returns spoken responses.

  2. The state transition diagram below illustrates mode-switching relationships. Chat Mode can be entered from any other mode by stating the wake word or pressing the right button briefly, as detailed in 4.4.2 Operational Steps.

4.4.2 Operational Steps ​

  1. After network configuration, the module displays the expression interface shown below:

  1. Speak the designated wake word, which defaults to Hello Hiwonder in English, or press button B on the right briefly to enter Chat Mode. A prompt tone sounds, the screen transitions to the chat dialog interface, and the module begins listening for speech.

  2. When entering Chat Mode via the spoken wake word, the system automatically transmits "Hello" as an opening greeting. The model generates a response displayed in the chat interface and broadcasts it via audio. This greeting can be interrupted, as detailed in 4.7 Smart Chat, before the module begins listening for speech.

  1. When entering Chat Mode by pressing the right button, the module begins listening immediately without an automatic opening greeting.
  1. During interaction in Chat Mode, the display can be configured to maintain the expression interface rather than displaying the chat dialog box. Refer to 4.5.2 Operational Steps for configuration instructions.

4.5 Expression Mode ​

NOTE

Before proceeding with this section, ensure the module is powered on and Wi-Fi and agent configurations are completed according to 4.1 WonderLLM Module Introduction and 4.2 Network Connection and Configuration.

4.5.1 Mode Overview ​

  1. This section introduces Expression Mode, where the module renders animated facial expressions.

  2. Mode transitions are illustrated in the diagram below. Expression Mode is entered through two methods: double-tapping the screen while in Camera Mode, or pressing the right button briefly while in Chat Mode when the module is not speaking.

4.5.2 Operational Steps ​

  1. After network configuration, the module enters Expression Mode by default.
  1. While in Expression Mode, pressing the left button toggles between Chat Mode and Expression Mode display settings. The current mode indicator appears at the top of the screen. The default setting is Chat Mode.

NOTE

  • Toggling these two modes configures the screen display style upon entering Chat Mode.

  • During left-button switching, the module remains in Expression Mode. Pressing the left button does not wake up or activate the module into active dialogue.

  • When the display style is set to Chat Mode, activating the module via wake words or the right button switches the screen to the chat dialog box to show dialogue content.

  • When the display style is set to Expression Mode, activating the module via wake words or the right button keeps the screen on animated expressions, reflecting dynamic facial feedback corresponding to model responses.

  1. After setting the display style to Expression Mode using the left button, activate the module into Chat Mode via the wake word or right button. The module renders expressive facial animations corresponding to spoken conversations, triggered through two prompt styles: describing a scenario where the module reacts automatically, or directly requesting an expression, such as "Show me an angry face".

NOTE

Phrasing does not require exact wording as long as the semantic intent is preserved.

4.7 Smart Chat ​

NOTE

Before proceeding with this section, ensure the module is powered on and Wi-Fi and agent configurations are completed according to 4.1 WonderLLM Module Introduction and 4.2 Network Connection and Configuration.

4.7.1 Standard Operation ​

  1. After powering on and establishing a network connection, wake up the module by stating the wake word or pressing the right button briefly to enter Chat Mode.

  2. Speak naturally to the module. Spoken queries are processed through cloud large language models, returning textual and vocal responses. The system maintains contextual memory across multi-turn conversations.

  3. After each conversational turn, including initial activation, the module continues listening. If no voice input is detected within 1 minute, listening terminates automatically, and the model broadcasts a departure response before entering sleep. Reactivate the module using the wake word or the right button to resume interaction.

  4. Active dialogues can also be ended manually by speaking phrases such as Goodbye or That is all for now. The module replies with a farewell message and concludes the listening cycle.

NOTE

Commands do not require exact phrasing as long as the semantic meaning is preserved.

  1. The WonderLLM AI module supports voice interruption. While the module is speaking, whether delivering a response, greeting, or farewell, pressing the right button terminates speech immediately and begins listening for the next voice input.

NOTE

Pressing the right button while the module is silent switches the system to Expression Mode, requiring reactivation.

  1. The WonderLLM AI module supports both English and Chinese speech recognition and synthesis. Switch the operating language dynamically using spoken requests, such as "Can you speak English with me?" or "Switch to Chinese".

NOTE

Phrasing does not require exact wording as long as the semantic intent is preserved.

4.8 Smart Visual Scene Understanding ​

NOTE

Before proceeding with this section, ensure the module is powered on and Wi-Fi and agent configurations are completed according to 4.1 WonderLLM Module Introduction and 4.2 Network Connection and Configuration.

The WonderLLM AI module integrates an HD camera to capture visual frames and analyze scenes using multimodal vision-language models, enabling environmental awareness.

4.8.1 Voice Interactive Control ​

  1. After powering on, the module enters the expression interface. State the wake word or press the right button briefly to access the chat interface and activate the module.
  1. Deliver voice commands using phrases such as: "Describe what you see in front of you" or "Take a photo."

NOTE

Commands do not require exact phrasing as long as the semantic meaning is preserved.

  1. Upon parsing the instruction, the camera captures a frame and displays it briefly on the screen for confirmation. The chat window logs the invoked capture routine without requiring user action, followed by visual analysis statements synthesized into speech. Responses are generated dynamically while maintaining scene fidelity.

NOTE

Scene understanding does not support continuous streaming analysis. It captures and evaluates a single visual frame upon receiving an operational command.

4.8.2 Touchscreen Trigger ​

  1. The module enters the expression interface after powering on.
  1. In the expression interface, double-tap anywhere on the touchscreen to switch to Camera Mode. The screen displays the live feed from the camera.
  1. In Camera Mode, tap anywhere on the screen once. The camera captures a frame, displays it briefly for visual verification, and returns to Camera Mode while broadcasting the audio description generated by the model.

NOTE

  • Double-tap the screen in Camera Mode to return to the expression interface.

  • Prior to tapping the screen in Camera Mode, the module only streams visual feeds without invoking AI model analysis.

4.9 Wake Word Modification ​

4.9.1 CI1302 Firmware Creation ​

NOTE

Supported wake word languages include English, Chinese, Japanese, Korean, Russian, Spanish, Thai, German, Indonesian, Vietnamese, French, Portuguese, Cantonese, Persian, and Turkish.

The CI1302 chip in the WonderLLM AI module processes wake word recognition. Configuring a customized name requires generating and flashing new CI1302 firmware. This section explains the firmware compilation procedure.

  • Wake Word Firmware Creation

NOTE

  • This guide uses the English wake word "HELLO HIWONDER" as an example. English wake words must be set in uppercase characters to take effect.

  • This procedure assumes an existing platform account and omits ChipIntelli platform registration.

  1. Navigate to the ChipIntelli Voice AI Platform to open the firmware generation portal.

  2. Click the language button in the upper-left corner to toggle between Chinese and English.

  1. Click Platform Features in the navigation bar, then select Product Firmware & SDK Deep Development under product development.
  1. Log in to the platform account when prompted. After logging in, click Offline Voice Recognition LLM Applications.
  1. Select the Product Firmware & SDK Deep Development entry from the submenu.
  1. On the redirected page, click on the left.
  1. Create a new product as shown below. Product name and description can be customized. Select Single Mic Voice Recognition for the application solution.

  1. In the parameter dialog, select General -> Smart Hub for product type and select CI1302 for the chip model. When prompted for the SDK name, select CI13XX_SDK_ASR_Offline.

  2. In the SDK version list, select the latest SDK release. The description field is optional. Click Established to proceed.

  1. After product creation, select the desired wake word language.

NOTE

Supported wake word languages include English, Chinese, Japanese, Korean, Russian, Spanish, Thai, German, Indonesian, Vietnamese, French, Portuguese, Cantonese, Persian, and Turkish.

  1. Configure basic project details. For English recognition, set the language type to English. Match the remaining parameters to the reference below and click Create.
  1. In hardware parameters, set the clock source to Internal RC and disable baud rate calibration.
  1. In debug serial configuration, set the UART0 pin mode to open-drain with support for an external 5 V pull-up resistor.
  1. In communication serial configuration, set the baud rate to 115200 bps and configure UART1 pin mode to open-drain with support for an external 5 V pull-up resistor. Click Continue to proceed.
  1. In the command editing section, select the playback voice timbre, such as Dane - English Male.

NOTE

  • This voice timbre does not affect the speech synthesis voice of the WonderLLM AI module during dialogue. To adjust the module voice, configure the bound agent in the XiaoZhi AI platform console as detailed in 4.2 Network Connection and Configuration, and reboot the device.

  • Playback functionality on the CI1302 chip is not used in subsequent applications, so any voice timbre selection is acceptable.

  1. Upload the command word spreadsheet. Locate the spreadsheet file under the directory 02 Attachments/07 Voice Command Protocol List under the same directory as this document, and drag it into the web upload field.

NOTE

To modify the wake word, open the English template spreadsheet and replace "HELLO-HIWONDER" with the desired custom wake word. English wake words must consist of uppercase characters only.

  1. Once uploaded, the command words populate the table below. Scroll to the bottom of the page and click Submit Now.

NOTE

Only the wake word entry in the CI1302 command table is utilized. Other unused command entries can be disregarded.

  1. Firmware compilation completes in several minutes. Click Download file to retrieve the compiled package.
  1. Extract the downloaded archive to access the compiled .bin firmware file. This file will be flashed to the CI1302 chip using the dedicated programming tool.

4.9.2 CI1302 Firmware Flashing ​

This section guides through flashing firmware to the CI1302 chip on the WonderLLM AI module.

  • Firmware Flashing
  1. Connect the lower Type-C port of the WonderLLM AI module to the computer using a USB cable.
  1. Open PACK_UPDATE_TOOL.exe located in 02 Attachments/02 CI1302 Chip Flashing Tool under the same directory as this document. Select chip model CI1302, then click Update.

NOTE

This demonstration flashes the factory firmware 'Hello Hiwonder' from 02 Attachments/03 CI1302 Chip Factory Firmware under the same directory as this document.

  1. Click Select firmware and choose the extracted .bin file obtained in the previous step.
  1. Select the corresponding COM port from the serial port dropdown list.
  1. Press and hold both buttons A and B on the WonderLLM AI module simultaneously to enter flashing mode. Maintain the hold until the flashing process begins, then wait for completion.
  • Wake Word Test

Once flashing completes, reboot the module. After network configuration finishes and the expression interface displays, speak the newly configured wake word. If the buzzer beeps once, the screen switches to the chat interface, and a greeting is spoken, the wake word modification is successful.

  • Extension

  1. To maintain consistent agent identity, the assistant nickname bound to the module can be updated to match the new wake word.

  2. Visit https://xiaozhi.me/ or click XiaoZhi AI Chatbot for direct access. Access the console, select the agent bound to the module, click Configure Role, update the assistant nickname to the new wake word, click Save, and restart the device.
